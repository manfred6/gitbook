# C2

Various C2 framework notes.

## Cobalt Strike

### Components

| Component | Purpose |
|:--:|:--:|
| Beacon | Endpoint implant (egress, peer to peer modes) | 
| Team Server | C2 server. Meant to be deployed in distributed mode, one c2 node per intrusion stage |
| Client | Connect to Team Server(s)|


### Loaders

Beacon is inherently a dll, not an executable file. Therefore, something needs to load it in order for the beacon to run.

#### Reflective Loader

Beacon used to use a reflective loader. This effectively fit into (`"stomped"`) the legacy bytes in the DOS-Header `_IMAGE_DOS_HEADER` struct, except the mandatory `e_magic` and `e_lfanew` members of this struct.
This shellcode stub then called the `ReflectiveLoader()` function exported by the dll, which contains the actual loader for the dll.
This `ReflectiveLoader()` function then allocates memory for the beacon dll, maps and initializes it, and calls `DllMain()`, effectively executing the beacon.
This requires the PE (dll) to actually export the `ReflectiveLoader()` function.

#### Prepended Loader
Now, Beacon uses a prepended loader, whereby the loader is prepended to the PE DOS-Header. This supports the actual PE-file being compressed and/or encrypted,
as the initial loader can be more complex due to its size not being constrained by the legacy space in the DOS-header. It also makes the loader independent of the payload it loads.
Whereas with the reflective loader, the dll being reflectively loaded requires a function to map and initialize itself (`ReflectiveLoader()`), this can be achieved by the prepended loader itself.

### Stages
\
The beacon payload itself (contained in the dll) can be staged or stageless. Staged payloads execute a small initial stub that fetches the full beacon from the teamserver. They are much smaller but come with less options for customization, and usually have less opsec as they for instance refrain from flipping memory permissions (`RW-`->`R-X`), and just use `RWX` to save bytes of shellcode.
The stager is usually packaged in a standalone PE file without a dedicated loader. The retrieved stage then includes beacon dll + loader.

### Payload Options

| Type | Description |
|:---:|:----:|
| HTML Application | HTML + VBScript, popular with phishing. Can run executables, powershell or VBA to run the stager. Exe drops to disk, rest runs in mem. |
| MSOffice Macro | VBA macro to be embedded into an Office document |
| Stager payload | Generate src files in variety of languages (similar to msfvenom) |
| Stageless payload | Almost identical to stager but heavier with more options |
| Windows Stager/Stageless | See above but outputs as compiled artifacts (PE files) |
